AquaLogic ESP32 Bridge Test - Quick Launcher Guide
===================================================

Important safety rules
----------------------
- Keep the ESP32 and tester laptop on the same private Wi-Fi.
- The bridge is the only component allowed to call ESP32 endpoints.
- Do not create a public tunnel to the ESP32. One temporary tunnel may expose
  the owner dashboard/API only.
- Do not change firmware, pins, wiring, or Wi-Fi behavior.
- v1 controls UV, normal LED, fish feeder, and controlled Pump A/B manual tests.
  Do not add pump schedules, pH auto-dose, automatic dosing, or feeder-test
  controls.
- Pump tests are for empty syringes or water only. Confirm the physical setup,
  keep Stop ready, and use the dashboard confirmation before Dispense/Test or
  Retract.
- A hardware timeout may mean the command already ran. The bridge never retries
  that physical command automatically.
- Keep the device key and bridge-config.json private; never commit, print, or
  share them.

OWNER COMPUTER: start AquaLogic
-------------------------------
1. Double-click start-esp32-bridge-owner.bat.
   - First run may install Python packages.
   - Leave the AquaLogic backend and dashboard windows open.

2. Check these local pages open:
   - http://127.0.0.1:8000/docs
   - http://127.0.0.1:5173

OWNER COMPUTER: make one temporary tunnel
-----------------------------------------
3. Double-click start-esp32-bridge-tunnels.bat.
   - It opens ONE ngrok window for the dashboard on port 5173.
   - Copy its HTTPS forwarding URL, for example:
     https://YOUR-NGROK-URL.ngrok-free.dev
   - Never create a tunnel to the ESP32.

4. Test the tunnel in a browser:
   https://YOUR-NGROK-URL.ngrok-free.dev/api/health

   It must show:
   {"status":"ok"}

5. Share the dashboard URL with the tester:
   https://YOUR-NGROK-URL.ngrok-free.dev

OWNER COMPUTER: provision the device once
-----------------------------------------
6. Open http://127.0.0.1:8000/docs and sign in with the administrator session.

7. Use GET /tanks to find the numeric ID of the intended test tank.

8. Use POST /devices with a new device ID and that tank ID:
    {"device_id":"esp32-test-01","tank_id":<TANK_ID>}

9. Copy the returned device_key immediately and securely give the tester:
   - the temporary dashboard/API URL ending in /api; and
   - the one-time device key.

HARDWARE TESTER LAPTOP: verify ESP32 and run bridge
---------------------------------------------------
10. Connect the laptop to the SAME private Wi-Fi as the ESP32.

11. In a browser, verify only this local page opens:
    http://<ESP32_LOCAL_IP>/data

    It should return JSON containing temp_c, ph_value, turbidity_ntu, and
    tds_ppm. Do not open any ESP32 actuator, pump, syringe, or dosing route
    manually.

12. Double-click start-esp32-bridge-tester.bat.
    - On first run it creates and opens bridge\bridge-config.json.
    - Fill the local /data URL, owner's HTTPS dashboard tunnel /api URL, the
      one-time device key, and the example polling values. Leave
      pump_manual_test_enabled false unless a controlled pump test is starting.
    - Save and close the file; the key/config must remain untracked.

13. Double-click start-esp32-bridge-tester.bat again to start the bridge.
    It preserves sensor polling, fetches pending admin commands, calls only the
    allowed local routes, and reports state/results without exposing the ESP32.

CONTROLLED PUMP TEST WINDOW
---------------------------
14. After the owner confirms the tank/device and the tester confirms empty
    syringes or water, set `pump_manual_test_enabled` to true in the untracked
    bridge config and restart the bridge.

15. In the admin tank dashboard, use only the Pump A/B Dispense/Test, Stop, and
    Retract controls. Dispense/Test cutoffs are limited to 100, 250, 500,
    1,000, 1,500, or 2,000 ms. Confirm the dialog before Dispense/Test or
    Retract; the bridge sends the exact firmware dispense route once and then
    the matching stop route after the cutoff.

16. Return `pump_manual_test_enabled` to false after the mechanical test and
    keep the config untracked. Do not enable schedules or pH auto-dose.

BOTH: check the dashboard
-------------------------
17. Open the shared dashboard tunnel URL, sign in as admin, and open the mapped
    tank.

18. Confirm sensor readings and the Actuator controls panel show current bridge
    freshness plus last-known UV, LED, feeder, and pump state.

19. Test one UV or LED command at a time. Test schedules and feeder config
    within the displayed limits. For Feed now, confirm the dialog only after
    checking the intended tank.

20. Check command history for actor, timestamp, status, and result/error.

21. Sign in as staff separately. Staff must not see usable controls, and direct
    actuator command/status/history calls must return 403.

22. Stop the tester bridge with Ctrl+C. After the freshness window, the tank
    should show stale/offline; it must not invent readings or claim hardware is
    off. Restart the bridge only when ready for another test.

After testing
-------------
- Stop the bridge, ngrok tunnel, backend, and dashboard windows.
- Keep bridge\bridge-config.json private and uncommitted.
- Record calibration observations separately. Do not edit firmware during this
  bridge test.
